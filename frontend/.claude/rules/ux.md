# UX / User Flow 기준

이 문서는 프론트엔드 구현 시 사용자 흐름과 UX 정책을 유지하기 위한 단일 기준이다. API 세부 스펙(엔드포인트, 요청/응답 구조, DB 상태값)은 다루지 않는다 — 그건 백엔드 계약이고, 이 문서는 "사람이 화면에서 무엇을 하고 무엇을 보는가"를 다룬다.

## 1. 주요 사용자

### 직원
- **목적**: 최소 조작으로 정확히 계산하고 다음 고객으로 넘어간다.
- **조작 범위**: 계산 화면(S-01~S-05) 전체 — 촬영, 인식 결과 정정, 직접 추가, 결제, 계산 취소.
- **사용 맥락**: 계산대에 서서, 손이 자유롭지 않을 수 있고, 대기줄 압박이 있는 상태에서 반복 조작한다. 정밀 조작을 요구하는 UI는 이 맥락에서 작동하지 않는다.

### 고객
- **목적**: 무엇을 얼마에 사는지 확인한다.
- **조작 범위**: CJ ONE 번호 입력 1곳(S-09)뿐. 그 외 모든 고객 화면은 표시 전용이다.
- **사용 맥락**: 계산대 맞은편에서 화면을 짧게 한 번 본다. 화면을 직접 만지지 않는다.

### 매니저
- **목적**: 상품·가격 관리, 판매 추세 확인, 재고 상황 파악.
- **조작 범위**: 운영 관리 화면(S-06, S-07, S-11, S-12). 계산 화면·고객 화면에는 진입 경로가 없다.
- **사용 맥락**: 매장 사무 공간 또는 계산대 여유 시간에 일/주 단위로 사용한다. 시간 압박이 낮다.

## 2. 화면별 사용자 역할

| Screen ID | 화면 | 사용자 |
|---|---|---|
| S-01 | 촬영 | 직원 |
| S-02 | 인식 결과·수정 | 직원 |
| S-03 | 결제 | 직원 |
| S-04 | 결제 완료 | 직원 |
| S-05 | 금일 판매 현황 | 직원 |
| S-06 | 상품 마스터 | 매니저 |
| S-07 | 판매 통계 | 매니저 |
| S-08 | 계산 목록·메뉴 추천 | 고객 |
| S-09 | CJ ONE 입력 | 고객 |
| S-10 | 계산 진행 상태 | 고객 |
| S-11 | 재고 관리 | 매니저 |
| S-12 | 재고 알림 | 매니저 |

Screen ID는 임의로 새로 만들거나 재배정하지 않는다. 위 표에 없는 화면이 필요하다고 판단되면 먼저 확인한다(§9 참고).

## 3. 주요 사용자 흐름 (직원 조작, 해피패스)

```
S-01 촬영
  → 인식
  → S-02 인식 결과·수정
      (필요 시 항목 정정 / 직접 추가 — §5 예외 흐름 참고)
  → 촬영 완료 확인 (총 개수 + 합계 금액 대조)
  → S-03 결제 진입
      → (선택) CJ ONE 입력 또는 건너뛰기 — 고객 화면(S-09)에서
      → 결제
  → S-04 결제 완료
      → 판매 데이터 반영 (금일 판매 현황·재고·판매 통계에 반영)
  → 직원 확인 → S-01로 복귀 (다음 고객)
```

- **촬영**: 트레이를 촬영해 인식을 시작한다. 촬영 처리에는 타임아웃이 없다 — 시스템이 자동으로 실패 판정하지 않고, 필요하면 직원이 직접 취소한다.
- **인식 결과 확인**: 화면의 질문은 "AI가 무엇을 찾았는가"가 아니라 "이 트레이의 판매 내역이 정확한가"다. 총 개수가 합계 금액보다 우선 확인 대상이다 — 금액은 항목이 맞으면 자동으로 맞지만, 반대는 성립하지 않는다.
- **항목 정정 / 직접 추가**: 목록에서 즉시 처리한다(별도 화면·모달 없음). 직접 추가는 조건 없이 상시 가능하며 별도 모드가 아니다.
- **촬영 완료 확인**: 결제 진입 시 항상 노출되는 확인 단계. 총 개수와 합계 금액을 보여주고 직원 육안 대조를 요구한다 — 이 확인이 데이터 정확도의 마지막 방어선이다.
- **CJ ONE 입력 / 건너뛰기**: 결제 진입 후 고객 화면에서 이루어진다. 건너뛰기는 정상 경로이며, 입력 버튼과 시각적으로 동등하게 취급한다.
- **결제 완료 이후**: 판매 데이터의 생성 지점이며 되돌릴 수 없다. 결제 완료 화면에는 정정 경로를 두지 않는다.

## 4. 화면 전환 원칙

- **계산 흐름(S-01~S-04)**: 네비게이션이 없다. 화면 전환은 흐름상의 버튼으로만 일어난다. 유일한 흐름 밖 진입점은 "금일 판매 현황(S-05)"이며 상시 노출한다.
- **고객 화면(S-08~S-10)**: 독립된 네비게이션이 없다. 전 구간이 직원 조작(계산 흐름)에 종속되며, 자체 트리거는 "CJ ONE 입력 완료/건너뛰기 → 진행 상태 전환" 하나뿐이다.
- **관리 화면(S-06, S-07, S-11, S-12)**: 사이드바로 자유롭게 이동한다. 직원 POS·고객 화면에는 관리 화면 진입 경로를 두지 않는다 — 매니저 전용 진입이다.
- 계산 중(항목이 담긴 상태)에 S-05로 이동해도 세션은 유지되고, 복귀 시 담긴 항목이 그대로 남는다. 계산대에 손님이 있는 상태에서 항목이 사라지면 사고이므로, 화면 이동만으로 세션을 폐기하지 않는다.

## 5. 예외 흐름

### 인식 실패 — 4갈래 분기
인식 결과가 만족스럽지 않을 때 직원이 고를 수 있는 경로는 아래 네 가지뿐이다. 새로운 경로를 추가하지 않는다.

| 상황 | 조치 |
|---|---|
| 1~2개 누락 | 직접 추가 |
| 트레이 넘침 | 추가 촬영 (배치 누적) |
| 전반적으로 부정확 | 다시 촬영 (전체 재시작) |
| 탐지 0건 또는 다시 촬영 2회 | 권유 배너 노출 → 직접 추가로 안내 (경로 강제 아님) |

### 다시 촬영
지금까지 담은 항목이 전부 사라지는 파괴적 조작이다. 확인 단계를 거친다.

### 계산 취소
담은 항목이 모두 사라지는 파괴적 조작이다. 확인 단계를 거치고, 주 조작(촬영/결제)에서 물리적으로 가장 먼 위치에 둔다. 반면 항목 1개 삭제는 파괴적 조작이 아니므로 확인 단계 없이 목록에서 즉시 처리한다.

### 결제 실패
결제 화면(S-03)에 머문 채 재결제 / 결제 수단 변경 / 계산 취소 선택지를 제공한다. 화면을 다른 곳으로 옮기지 않는다 — 손님 앞에서 직원이 처음부터 다시 밟게 하지 않기 위함이다. 고객 화면에는 실패 사유를 노출하지 않고 "재시도 중" 수준의 중립적인 진행 표시만 한다.

### 회원(CJ ONE) 조회 실패
번호 미입력·건너뛰기(비회원, 정상 경로)와 조회 실패(등록되지 않은 번호, 오타 가능성)를 구분한다. 조회 실패 시 재입력 기회를 주고 건너뛰기도 함께 제공한다.

### 장치 무응답 / 스캐너 장애
별도 모드가 아니다. 직접 추가만으로 촬영 없이 계산을 완결할 수 있다.

## 6. 고객 화면의 조작 범위

고객이 조작할 수 있는 지점은 **CJ ONE 번호 입력(S-09) 1곳뿐**이다. 그 외 모든 고객 화면(S-08, S-10)은 표시 전용이며, 직원 조작 결과를 그대로 미러링한다. 고객 화면에 새로운 조작 지점을 추가하지 않는다.

## 7. 직원 / 고객 / 매니저 화면 간 책임 분리

- 계산 흐름의 조작 주체는 전부 직원이다. 고객 조작은 S-09 하나로 격리되어 있다.
- 고객 화면은 직원 상태를 구독하는 파생 뷰다 — 별도의 조작 로직이나 상태를 갖지 않는다.
- 매니저 관리 화면은 직원 POS·고객 화면과 진입 경로가 분리되어 있다. 서로의 화면으로 넘나드는 경로를 만들지 않는다.

## 8. UX 핵심 용어 (고정 표기)

아래 용어는 UI에 노출되는 고정 표기이며, 임의로 바꾸거나 다른 표현으로 대체하지 않는다.

| 개념 | 표기 | 금지 표현 |
|---|---|---|
| 최초 인식 | 촬영 | 스캔, 찍기 |
| 전체 재시작 | 다시 촬영 | 재촬영, 초기화, 다시 스캔 |
| 배치 누적 | 추가 촬영 | 재스캔, 분할 촬영 |
| 직전 배치 취소 | 직전 촬영 취소 | 되돌리기 |
| 개별 수동 추가 | 직접 추가 | 수동 입력 |
| 세션 취소 | 계산 취소 | 세션 종료, 폐기 |

**고객 화면 금지어**: 신뢰도·배치·임계값·정정 이력·미탐·스냅샷·AI 인식과, 촬영 계열 용어(촬영/다시 촬영/추가 촬영/스캔) 일체를 노출하지 않는다. 고객 화면은 표시 전용이므로 이 용어들이 등장할 자리가 구조적으로 없다.

## 9. 변경 금지 사항 (폐기/미확정 기능)

- **세트 자동 적용 / 세트 할인**: 폐기된 기능이다. 다시 구현하지 않는다. (구 FR-06 "세트 자동 적용")
- **CJ ONE 차등 적립(제휴·할인 시 0.1%)**: 폐기됐다. 적립률은 등급 무관 **0.5% 단일**이다(§10 참고).
- **본사 운영 대시보드, 직원 로그인/PIN/화면 잠금, 재고 스냅샷·품절 예측·생산 추천, 실제 POS 결제망/발주 시스템 연동**: 범위 밖이다. 요청 없이 추가하지 않는다.
- 매니저용 KPI 요약 대시보드(운영 현황 화면)와 매니저용 별도 판매 내역 화면은 **아직 화면으로 확정되지 않았다** — 필요하다고 판단되어도 임의로 새 화면을 만들지 않고 먼저 확인한다.

## 10. Step 3 결정사항 (확정 기준)

문서 간 충돌이 있던 항목에 대해 아래와 같이 확정했다. 원본 참고 문서(UX 설계서/유저 플로우 명세서)와 이 결정이 다르면 **이 결정을 따른다**.

| 항목 | 결정 |
|---|---|
| 세트 자동 적용 기능 | 폐기 확정. 재구현하지 않는다 |
| CJ ONE 적립률 | 0.5% 단일 고정(등급별 차등 없음). API 명세서 기준 채택 |
| 매니저용 운영 현황(KPI) 대시보드 화면 | 보류 — 화면으로 만들지 않는다. 필요 시 별도 확인 |
| 매니저용 별도 판매 내역 화면 | 보류 — 별도 화면을 만들지 않는다. 필요 시 별도 확인 |
| 재고 관리(S-11)·재고 알림(S-12) 접근 제어 | 프론트엔드 라우팅 단에서만 매니저 전용으로 제한한다 |

---

이 문서에 없는 사용자 흐름·화면·역할이 필요하다고 판단되면, 추측해서 구현하지 말고 먼저 확인한다.
