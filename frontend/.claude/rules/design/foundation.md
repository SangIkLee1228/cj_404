# Design Foundation — POS · Dashboard 공통

POS와 대시보드가 공통으로 따르는 디자인 원칙만 담는다. 두 서비스에서 값이 다를 수 있는 항목(터치 타깃 크기, 여백, 화면 밀도, 컴포넌트 스타일 등)은 여기 올리지 않고 `pos.md` / `dashboard.md`에서 각각 정의한다.

## 확정되지 않은 값에 대한 원칙

Typography(서체·크기 스케일), Brand Color/Semantic Color(실제 hex·토큰 값), Border, Radius, Shadow의 **구체적인 수치는 아직 확정되지 않았다.** 참고한 소스 문서(UX 설계서·유저 플로우 명세서·API 명세서) 어디에도 실제 색상 코드, 폰트, spacing/radius 값이 정의되어 있지 않다.

값이 확정되기 전까지:
- 임의의 hex 색상, 폰트 패밀리, px/rem 수치를 만들어 쓰지 않는다.
- 값이 필요하면 기존 코드베이스에 이미 있는 값(예: Tailwind 기본값)을 그대로 쓰거나, 확인이 필요하면 먼저 확인한다.
- 이 문서가 업데이트되어 실제 토큰 값이 채워지면 그때부터 그 값을 기준으로 따른다.

## 공통 브랜드 방향

- 그래픽 리소스(아이콘·목업·토스트 등 타사 자산)를 그대로 가져다 쓰지 않는다. 참고한 것은 원칙이지 자산이 아니다.
- 라이팅은 서피스마다 톤이 다르다(POS: 평서·명령형 / 고객 화면: 해요체 / 대시보드: 평서형). 실제 톤은 `pos.md`/`dashboard.md`에서 정의하되, 아래 공통 규칙은 모든 서피스에 동일하게 적용한다.

## 공통 라이팅 원칙

- **사과하지 않는다** — 무슨 일이 있었고 지금 뭘 하면 되는지만 말한다.
- **선택지를 준다** — 오류 안내에는 항상 다음 행동 버튼이 붙는다.
- **버튼은 실행 결과를 그대로 말한다** — "확인" 대신 "다시 촬영"처럼 구체적으로 쓴다.
- **오류 문구는 두 문장을 넘지 않는다** — [무슨 일이 있었는지] + [지금 뭘 하면 되는지].
- **추정값은 추정임을 밝힌다** — 예: "재고 12개"가 아니라 "추정 12개".
- **확인 버튼에 "예/아니오"를 쓰지 않는다** — 무엇에 동의하는지 버튼 라벨만 보고 알 수 있어야 한다.

## 상태 표현 원칙

- **색만으로 상태를 전달하지 않는다** — 상태는 항상 색 + 텍스트 + 형태(배지, 아이콘 등) 조합으로 전달한다.
- 배지·상태 표시의 정확한 형태(좌측 바, 텍스트 배지 등)는 서피스별 문서(`pos.md`, `dashboard.md`)에서 정의한다.

## 기본 Button 위계

액션은 아래 네 범주로 구분한다. 실제 배치·크기는 서피스별 문서에서 정의하되, 범주 구분과 파괴적 액션에 확인 단계를 두는 원칙은 공통이다.

| 범주 | 설명 |
|---|---|
| 주 조작 | 화면의 핵심 행동 (예: 촬영, 결제) |
| 보조 조작 | 주 조작을 돕는 부가 행동 (예: 직접 추가) |
| 파괴적 조작 | 데이터가 사라지는 행동 (예: 계산 취소, 다시 촬영). 반드시 확인 단계를 거치고, 주 조작과 시각적으로 명확히 구분한다 |
| 이탈 조작 | 현재 흐름을 벗어나는 행동 (예: 다른 화면으로 이동) |

## Modal 기본 원칙

- Modal(팝업·안내)은 실제 화면(Page)과 구분되는 별도 레이어다.
- 파괴적 조작을 확인하는 Modal은 결과를 구체적으로 명시한다(예: "담은 항목이 모두 사라집니다") — "예/아니오"로만 묻지 않는다.

## Input 기본 원칙

입력 필드의 구체적인 스타일(테두리, 포커스 색 등)은 미정이다. 다만 아래 동작 원칙은 공통이다.
- 오타 확인이 필요한 입력(예: 전화번호)은 입력 중 전체 값을 노출한다. 마스킹은 입력 완료 후에만 적용한다.

## Badge 기본 원칙

- 배지는 단독으로 상태를 전달하지 않는다 — 위 상태 표현 원칙을 따른다.
- 배지의 정확한 형태·크기는 서피스별 문서에서 정의한다.

## Focus / Disabled

- 포커스 상태는 시각적으로 명확히 구분되어야 한다(구체적 스타일은 미정).
- Disabled 상태의 정확한 표현은 미정이다 — 임의로 opacity·색상 값을 만들지 않는다.

## 접근성 공통 원칙

- 색 단독 전달 금지(위 상태 표현 원칙과 동일).
- 본문 명암비 4.5:1, 큰 텍스트 3:1 이상을 기준으로 한다.
- 터치 타깃 최소 크기는 서피스별로 다르므로 `pos.md`/`dashboard.md`에서 정의한다.
