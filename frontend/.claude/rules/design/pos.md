# Design — POS · 고객 표시 화면

직원용 계산 화면(POS)과 그 위에 플로팅되는 고객 표시 화면 전용 규칙이다. POS는 **빠른 인지와 즉시 조작**이 정보 밀도보다 우선하는 현장형 인터페이스다 — 서서, 손이 자유롭지 않을 수 있고, 대기줄 압박이 있는 상태에서 조작한다.

## POS Layout

| 항목 | POS (S-01~S-05) | 고객 표시 화면 (S-08~S-10) |
|---|---|---|
| 기기 | 터치 태블릿(가로) | 세로 디스플레이(플로팅 구현) |
| 기준 캔버스 | 1280×800 | 논리 720×1152(5:8) / 구현 390×624 고정, 좌측 상단 |
| 입력 | 터치 + 물리 키보드 | 터치 1지점(CJ ONE 입력만) |
| 시간 압박 | 매우 높음 | 없음 |
| 스크롤 | 결과 목록만 허용 | 금지 |

- POS 목록은 스크롤 없이 8개 이상 노출한다(트레이 1회분의 일반적인 수량). 초과분만 스크롤.
- 고객 화면 목록은 6개까지 노출하고 초과분은 "외 N개"로 축약한다. 축약 시에도 총 개수·합계 금액은 항상 전량 기준으로 표시한다 — 고객이 확인해야 하는 건 개별 항목이 아니라 총액이다.
- 계산 흐름(S-01~S-04)에는 네비게이션을 두지 않는다. 화면 전환은 흐름상의 버튼으로만 일어난다.

## 촬영 영역

- 인식 처리에는 타임아웃이 없다. 자동 판정 대신 "처리 중" 표시 + 취소 버튼을 둔다.
- 진행률(퍼센트 등 가짜 진행률)을 표시하지 않는다 — 소요 시간을 예측할 수 없고, 실제보다 오래 걸리면 신뢰를 잃는다.
- 촬영·다시 촬영·추가 촬영은 결과가 전혀 다르므로(신규 / 전체 재시작 / 누적) 같은 크기·모양으로 나란히 두지 않는다.

## 인식 결과 영역

- 계산 화면이 답해야 할 질문은 "AI가 무엇을 찾았는가"가 아니라 "이 트레이의 판매 내역이 정확한가"다. 정보는 이 순서로 배치한다.

  1. 총 개수 — 트레이 실물과 대조하는 유일한 값
  2. 합계 금액 — 고객에게 말해야 하는 값
  3. 항목 목록 — 개별 확인·정정 대상
  4. 인식 결과 시각화(바운딩 박스 등) — 판단 근거일 뿐, 목록보다 크게 두지 않는다
  5. 메뉴 추천 — 부가 정보

- 확인 필요 항목(임계값 이하로 인식된 항목)은 색 + 텍스트 배지 + 좌측 바 3중으로 표시한다. 수치(신뢰도 %)는 절대 노출하지 않는다.

## 계산 상품 Row

행 높이 최소 72px. 좌→우 순서 고정:

```
[상태 바] 상품명 · 구분 표시 | 단가 | 수량 조작 | 금액 | 삭제
```

- 상태 바(좌측 세로 바)는 확인 필요 상태에만 표시하고, 배지·텍스트와 함께 3중으로 전달한다.
- 상품명이 행에서 가장 큰 글자다 — 직원이 대조하는 건 상품 종류지 금액이 아니다.
- 직접 추가 항목만 구분 표시한다. 직원이 정정한 항목은 별도 표시하지 않는다(이미 본인이 고친 것이므로).

## 수량 조작

- 증감 버튼은 행 안에서 끝난다 — 별도 화면·모달로 빼지 않는다. 수량 변경은 정정 중 가장 빈번한 조작이므로 목록에서 즉시 처리되어야 한다.
- 터치 타깃은 56px을 확보한다(§터치 타깃 참고).

## 직접 추가

- 조건 없이 상시 가능한 보조 조작이다. 별도 모드가 아니다.
- 인식이 실패해도(탐지 0건, 다시 촬영 2회) 직접 추가만으로 촬영 없이 계산을 완결할 수 있다.

## 주요 CTA

- 촬영 완료 확인 모달은 결제 진입 시 항상 노출되며 "총 개수 + 합계 금액"과 "추가 촬영 / 결제 진행" 선택지를 보여준다.
- 메뉴 추천은 상시 노출·고정 인라인 영역이다(오버레이·팝업·바텀시트 형태 금지). 결제 진행 중에도 위치·형태를 바꾸지 않는다. 담기 조작은 직원만 한다 — 고객 화면 쪽 메뉴 추천은 표시 전용이다.

## 결제 영역

- 등급 할인·CJ ONE 적립은 직원(S-03)과 고객(S-09/S-10) 화면 모두에 등급명과 금액을 노출한다.
- 적립률은 등급 무관 **0.5% 단일**이다(`rules/ux.md` §10 참고 — 차등 적립은 폐기됨).
- 결제 실패 시 S-03에 머문 채 재결제 / 결제 수단 변경 / 계산 취소 선택지를 제공한다. 화면을 다른 곳으로 옮기지 않는다.

## 계산 취소 / 다시 촬영 등 파괴적 액션

- 계산 취소, 다시 촬영, 직전 촬영 취소는 파괴적 조작이다. 반드시 확인 단계를 거치고, 주 조작(촬영/결제)에서 물리적으로 가장 먼 위치에 둔다.
- 확인 문구는 결과를 구체적으로 명시한다: "담은 항목이 모두 사라집니다" / "지금까지 담은 항목이 사라집니다".
- 확인 버튼에 "예/아니오"를 쓰지 않고 실행 결과를 그대로 라벨로 쓴다: "계산 취소 / 돌아가기", "다시 촬영 / 돌아가기".
- 항목 1개 삭제는 파괴적 조작이 **아니다** — 목록 행 안에서 즉시 처리하고 확인 단계를 두지 않는다. 확인 단계를 두면 대기줄 압박 상황에서 병목이 된다.
- 키보드 단축키(Space=촬영, Enter=결제 진입, Delete=삭제, Esc=취소)를 지원하되, 파괴적 조작에는 단축키를 배정하지 않는다.

## Modal

- foundation의 Modal 기본 원칙을 따른다.
- 촬영 완료 확인, 파괴적 조작 확인은 PAGE 위에 뜨는 별도 레이어(Modal)로 처리한다.

## 고객용 Floating Display

- 좌측 424px(390 + 여백)을 레이아웃 단계에서 예약해 직원 작업 영역과 겹치지 않게 한다.
- **프레임은 어떤 UI 상태에서도 외곽 크기를 바꾸지 않는다.** 내부 콘텐츠만 교체한다 — 프레임이 흔들리면 고객이 화면 전환을 오인한다.
- 영역 구조(상단/중앙/하단)는 상태가 바뀌어도 동일하게 유지한다. 상단에는 항상 금액(또는 브랜드), 중앙에는 목록/입력/진행 상태, 하단에는 추천·건너뛰기 등을 배치한다.

## 고객 화면과 직원 화면의 표현 차이

| | POS | 고객 화면 |
|---|---|---|
| 톤 | 평서·명령형 | 해요체, 짧은 문장 |
| 회원명/휴대폰 표시 | 실명·전체 노출 | 마스킹 (예: 한*원, 010-****-5678) |
| 신뢰도/시스템 용어 | — | 절대 노출하지 않음 |
| 결제 실패 표현 | 사유·선택지 제공 | 사유 숨기고 "재시도 중" 중립 표시만 |

## 고객 화면의 유일한 조작 지점

CJ ONE 번호 입력(S-09) 1곳뿐이다. 건너뛰기 버튼은 입력 버튼과 **동일한 크기·명도 대비**로 둔다 — 어느 한쪽을 시각적으로 위축시키지 않는다.

## 터치 타깃

| 화면 | 최소 터치 타깃 | 목록 행 높이 |
|---|---|---|
| POS | 56px | 최소 72px |
| 고객 표시 화면 | 72px (조작 지점은 CJ ONE 입력 1곳뿐이므로 그 하나를 크게 잡는다) | 40px (조작 대상이 아니므로 가독성 기준) |

## 오류 및 확인 메시지

| 상황 | 문구 톤 |
|---|---|
| 탐지 0건 / 인식 응답 오류 | "인식된 빵이 없습니다. 다시 촬영하거나 직접 추가하세요" 형태 — 사과 없이 다음 행동 제시 |
| 장치 무응답 | "직접 추가로 계산하세요" — 촬영 없이 대체 경로 제시 |
| 결제 실패 | S-03에 머문 채 재결제/수단 변경/계산 취소 선택지. 고객 화면에는 사유 없이 중립 표시만 |
| 빈 상태(항목 0개, 오늘 판매 없음 등) | 오류가 아니다. 경고색을 쓰지 않고 다음 행동만 안내 |

## 접근성

- 계산 화면 전체가 키보드로 도달 가능해야 한다.
- 확인 필요 항목 등 상태 표시는 색 단독 전달 금지 원칙(foundation 참고)을 그대로 따른다.
- 고객 화면 글자 크기는 60~80cm 시청 거리를 기준으로 하며, 금액을 가장 크게 표시한다.
