# CJ_404 Frontend — Claude 작업 가이드

## 서비스 개요

바코드가 없는 즉석빵을 트레이째 촬영해 품목 단위 판매 데이터를 자동으로 생성하는 매장용 POS 보조 시스템(스냅빵)이다. 계산 병목 해소가 아니라, 애초에 존재하지 않던 판매·재고 데이터를 만들어내는 것이 서비스의 존재 이유다. 산출물이 좁은 만큼 데이터 정확도가 서비스 가치의 대부분을 차지한다.

## 주요 사용자

- **매장 직원** — 계산대에서 촬영·정정·결제를 수행하는 주 조작자. 서서, 손이 자유롭지 않을 수 있고, 대기줄 압박이 있는 상태에서 조작한다.
- **고객** — 계산대 맞은편에서 화면을 보기만 한다. CJ ONE 번호 입력 1곳만 예외적으로 조작한다.
- **매니저** — 상품·재고·판매 통계를 조회·관리한다. 계산 화면·고객 화면에는 진입하지 않는다.

## frontend가 담당하는 화면 영역

| 화면군 | 사용자 | 성격 |
|---|---|---|
| 계산 화면 (POS) | 직원 | 촬영→인식→정정→결제. 시간 압박 높음 |
| 고객 안내 화면 | 고객 | POS 위 플로팅, 표시 전용 (CJ ONE 입력 1곳 예외) |
| 운영 관리 화면 (대시보드) | 매니저 | 상품·재고·판매 통계 조회/관리. 시간 압박 낮음 |

## `.claude/rules` 구조

```
rules/
├── ux.md                  사용자 흐름·역할·UX 정책 기준
└── design/
    ├── foundation.md      POS·대시보드 공통 디자인 원칙
    ├── pos.md              POS·고객 화면 전용 디자인 규칙
    └── dashboard.md        대시보드 전용 디자인 규칙
```

`rules/frontend.md`는 아직 없다 — 상태 관리, API 호출 방식, 폴더 아키텍처, 테스트 환경, 코딩 컨벤션이 아직 확정되지 않았기 때문이다. 없다는 것 자체가 "미정"이라는 뜻이며, 이 부분을 임의로 정의하지 않는다.

## 작업 전 확인 순서

1. **`rules/ux.md`** — 어떤 화면을 작업하든 가장 먼저 읽는다. 사용자 흐름·역할·조작 범위·예외 처리·변경 금지 사항이 정리돼 있다.
2. **`rules/design/foundation.md`** — POS·대시보드 공통 디자인 원칙.
3. 작업 대상이 POS/고객 화면이면 **`rules/design/pos.md`**, 대시보드면 **`rules/design/dashboard.md`**를 추가로 읽는다.

## 기본 원칙

이 저장소의 프론트엔드 구현은 위 `rules/` 문서에 확정된 내용을 기준으로 한다. 문서에 없는 내용은 추측해서 채우지 않고 먼저 확인한다.

### 임의로 변경·추가하면 안 되는 것

- 기존 User Flow(화면 전환 순서, 분기 조건)를 임의로 변경하지 않는다.
- FR 번호와 Screen ID(S-01 등)를 임의로 생성하거나 변경하지 않는다.
- 폐기된 기능(예: 세트 자동 적용, CJ ONE 차등 적립)을 다시 구현하지 않는다.
- `rules/ux.md`에 정의되지 않은 화면·기능을 임의로 추가하지 않는다.
- UX 규칙과 디자인 규칙이 충돌하는 것처럼 보이면 추측해서 진행하지 않고 사용자에게 확인한다.
- 상태 관리 방식, API 호출 방식, 폴더 구조, 코딩 컨벤션, 테스트 도구 등 아직 정의되지 않은 개발 아키텍처·라이브러리를 임의로 도입하지 않는다.
